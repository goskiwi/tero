# Tero 模块对照实验：首轮结果

日期：2026-09-09。被测 Runtime 提交：`2d41fb1199e9023b0eaca7f0413e48d40269c3a2`。实验期间未修改 Runtime。
上下文和记忆使用 DeepSeek V4 Flash 官方 Responses API；恢复场景使用脚本化模型和真实文件／进程。
每个条件先执行一次，保留失败，不把首轮样本结果解释为统计稳定性。

## 1. 上下文：12 组固定配置，开启／关闭治理

配置为 3 档历史单元数（8、24、48）× 2 档工具结果占比（约 1/4、3/4）× 2 档当前请求长度。
历史是受控合成回放，其中读取结果由真实文件工具生成；不是 12 个自然软件项目。
每组同一历史分别直接组装与调用当前 ContextManager。两组都已有工具级预览限长，实验比较的是后续
历史裁剪／摘要治理的增量效果。关闭 RepoMap 和长期记忆，主模型探针不调用额外工具，避免补读掩盖遗漏。

检查六项已记录事实：任务编号、API 名、金额单位、单测状态、集成测试状态、未完成工作。
每个主请求必须保留当前请求原文和完整工具调用配对。摘要开销另计，不混成免费压缩。

| 指标 | 未启用上下文治理 | 启用治理 |
| --- | ---: | ---: |
| 主请求平均实际输入 Token | 17,557.33 | 9,236.17 |
| 六项事实全部答对 | 12/12 | 11/12 |
| 单字段答对 | 72/72 | 69/72 |
| 当前请求原文保留 | 12/12 | 12/12 |
| 工具调用配对正确 | 12/12 | 12/12 |
| 平均准备＋回答耗时 | 2.796 秒 | 6.917 秒 |

主请求输入按总量计算下降 **47.39%**：`1 - Σ实验输入 / Σ对照输入`，12 对都有实际 usage。
这不是全任务费用降幅。实验组摘要生成增加了等待和输出；含摘要的已报告输入分别为 175,222 与对照
210,688，已报告输出为 10,232 与对照 3,627。实验组有一次重试缺少 usage，不能当作完整计费总量。

失败配置为长历史、高工具占比、长请求（48-1-1）：摘要把已记录测试状态和待办改写成“没有执行工作、
等待用户指令”，最终单测／集成测试返回 UNKNOWN，待办也错误。不能据此写“压缩后关键信息不丢失”。

## 2. 长期记忆：6 个跨 Session 任务，三组对照

任务包括报告语言、报告顺序、金额约定、需求文档指针、约定纠正、显式遗忘。
用户陈述经当前 MemoryStore.extract 真实提取和保存；查询时新建 Session，不携带旧 Transcript。
分别使用相关记忆、关闭记忆、其他类别的真实已提取记忆作为干扰。答案未知时必须返回 UNKNOWN。
这是跨会话约定回答测试，不是代码文件摘要或重复读取实验。

| 指标 | 相关记忆 | 关闭记忆 | 无关记忆 |
| --- | ---: | ---: | ---: |
| 预期答案正确 | 4/6 | 1/6 | 1/6 |
| 召回错误 | 2 | 0 | 0 |

相关组正确率 66.7%，对照为 16.7%，本样本差 **50 个百分点**；不代表通用记忆准确率。
两个失败分别是语言和文档指针：记录已经保存，但召回输出上限为 512 token，推理占用额度后返回
`max_output_tokens` 截断，最终只能回答 UNKNOWN。纠正与遗忘各一个场景通过。
无关组的 6 次召回均未选择无关卡片，回答 UNKNOWN；其中遗忘题的 UNKNOWN 符合预期，其余题无信息可答。
相关组查询平均约 3.605 秒，关闭组约 1.417 秒；记忆有额外开销。

## 3. 恢复与工具治理：10 个故障／边界场景

| 场景 | 结果 |
| --- | --- |
| 保存 pending 后子进程退出 | 未重放旧调用，重新继续后验收通过 |
| 保存 running、尚未修改时退出 | 先按未知观察，再继续，验收通过 |
| 原子替换后、结果保存前退出 | 根据前像和收据观察当前文件，不重复施加旧修改，验收通过 |
| 上述退出后又发生外部修改 | 保留外部内容和未知状态，不自动覆盖 |
| Shell 超时 | 调用结束，所属进程停止 |
| 用户取消运行中进程 | 取消生效，所属进程停止 |
| 同一审批连续拒绝 | 仅询问一次，重复失败后停止，没有写文件 |
| 大结果分页取回 | 找回已保存诊断，原命令只运行一次 |
| 不支持的 Session 格式 | 明确拒绝恢复 |
| 跨 Session 读取 Artifact | 拒绝读取其他 Session 的内容 |

**10/10 符合各自预期**。其中 4 个实际子进程崩溃恢复场景，3 个自动继续并验证，1 个保留外部修改后
安全停止。不要将“10/10 符合预期”说成“100% 自动恢复完成”。

## 方法修正与结果保留

第一轮上下文题干使用 task ticket，模型返回 task_ticket 等键，评分却只认 ticket。首轮严格分数
混入格式歧义，因此改为明确枚举六个键，完整重跑全部 24 个对照请求；没有映射别名来强行通过。
首轮无关记忆提取因字段为空失败，没有实际干扰卡片。这 6 个查询不构成有效无关记忆对照，已单独
标记；替换为其他类别已通过正常提取保存的记忆后只重跑无关组。相关组的两次真实失败未被重跑覆盖。

## 复现与证据

```bash
python -m evaluations.module_benchmarks --suite context
python -m evaluations.module_benchmarks --suite memory
python -m evaluations.module_benchmarks --suite recovery
```

当前脚本使用明确键名，并在准备好六组记忆后选择其他类别作为噪声；样本准备失败会显式计入错误。
每次使用新输出目录，不覆盖已测行。对照配置、问答、逐场景结果见 `benchmarks/results/module-first-pass-20260909/`。
完整输入、Trace、Session、Artifact 保留在 `.tero/experiments/` 下对应三次实验目录。
本轮没有兼容旧 Pico 的评测接口，也没有为了让结果变好修改被测 Runtime。
