## 发现与修改

AgentLoop 原先不会因相同操作成功而清除旧失败记录。例如一次命令失败后已成功，后续一次新失败
仍可能被提示为连续失败。现在成功的同名、同规范化参数调用清除该记录；无关读取仍不清零。
没有增加调用缓存、自动重试、业务进展评分或新的持久化格式。

工具结果只序列化一次，再用于历史保存和副作用观察；完成拒绝计数的重置条件改为有名称的局部变量。
没有为形式拆文件、创建额外接口或更换 Session 快照架构。

## 主流程阅读结论

1. runtime.py 装配配置、Session、Context、Provider 和工具依赖。
2. agent_loop.py 驱动模型轮次，完整回复先保存，随后执行工具、逐个保存结果。
3. context.py 保护当前需求和未观察尾部，摘要只处理已观察的旧完整单元；失败不安装候选。
4. tool_executor.py 提供准入、文件修改、Shell 观察及明确恢复指引；commands.py 管理输出和进程组。
5. completion.py 对配置的验证执行真实命令并检查文件状态；session.py 是恢复依据，Trace 用于诊断。
6. applications/coding.py 生成本地交付报告，不自动 Commit 或 Push。

当前可按这条顺序讲解，无需继续架构重构。测试通过不等于证明所有业务语义、外部副作用或完整 1M
长上下文都正确；真实长任务结果仍按对应历史报告的范围引用。
