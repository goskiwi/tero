# 设计说明

## 三种数据，各有一个归属

**Session** 保存原始历史、六段摘要、摘要覆盖位置和当前运行信息。一次工具调用所在的模型
回复先保存，再执行；每个结果随后保存。同一回复的调用及全部结果组成一个历史单元。
Resume 给缺少结果的调用补充中断说明，不猜测命令是否实际执行，也不自动重放。

**长期记忆** 只保存 user、feedback、project、reference 四类信息，不保存代码摘录和临时待办。
召回时模型只选择 ID；提取时模型只返回修改操作；文件权限与实际保存由 Python 管理。
来源必须对应本次任务的用户消息。新要求优先；模型仍可能判断错误，因此支持直接查看和删除。

**Trace/Report** 是可读诊断输出，不重放它们来驱动主状态，没有 RunProjection、双重版本链
或第二份可变任务进度。六段摘要是派生上下文，不是代码正确性的证明。

**RepoMap** 是当前仓库的派生导航。它在正常历史组装或压缩完成后使用剩余预算，不为了导航
挤掉必需内容，也不单独触发压缩。代码签名和排名不写入 Session 或长期记忆；恢复后从文件重新生成。
查询依据为当前用户请求和本次实际观察到的文件路径，解析缓存随文件变化失效。

## 顺着一次编辑阅读

1. 模型通过原生工具调用提出 edit。
2. Session 保存包含该调用的模型回复。
3. ToolExecutor 检查参数、路径、写入范围和审批。
4. 对照最近 read 的版本，检查旧文本唯一匹配。
5. 在临时文件中构造完整内容，提交前再检查目标和版本。
6. 原子替换后观察版本；返回明确结果并保存到 Session。

如果第 5 步前拒绝，工具没有产生文件修改；如果执行阶段异常且结果不确定，报告 unknown。
不把“退出码为零”或“没有观察到文件变化”等同于整个任务正确。

## 上下文与恢复

原始历史始终保留。`observed` 记录最后一次成功主模型请求所观察的完整历史边界。
主请求失败或溢出不会推进它；新回复与工具结果直到下一次主请求成功前都属于原文保留区。
当前用户请求原样保留；近期已观察交互按完整单元保留；只对更早单元生成摘要。
当前需求可作为独立参考帮助摘要识别任务，但主输入中仍保留原文，不依赖摘要重述。

摘要输入是带角色标签的文本。旧成功 read/search/list 的正文超过 2,000 字符时提供有标记节选，
调用参数、结果状态和版本等元数据仍保留；失败、修改、Shell／验证证据不走这条节选规则。
内部推理不当作执行事实重复交给摘要器。这里只处理摘要输入投影，不修改 Session。

输出为 Markdown，六段是内容指引，不做逐字标题匹配。检查非空、未截断、正文预算、整体缩小
及硬窗口。空或超长允许一次针对性修正；拒绝候选及其长度、原因进入 Trace，不能成为有效摘要。

失败记录保存实际来源区间、当前摘要覆盖边界、任务锚点、预算和模型路由。只有成功主请求
已观察的完整单元可入摘要，现有单写者循环随后不修改这些单元，因此追加尾部不需要内容 hash。
这个前提不支持外部原地修改 Session；这里不提供分支、Rewind 或并发写入能力。
相同条件的自动失败被抑制，手动 `/compact` 可显式重试，成功后清除当前失败状态；Trace 保留历史。
NoOp（没有符合条件的旧历史）与 Failed 分开记录。提前压缩失败且原输入仍能装入窗口时继续；
Provider 已报告溢出或本地预算不够时停止。取消、整个任务超时、存储错误不作为可选失败吞掉。
单次摘要请求超时与整个任务超时分别处理。

Session 使用一次完整原子替换保存。恢复时检查格式、目录归属和覆盖位置。新的请求重新获得
本次运行预算；文件版本缓存为空，修改前重新读。Checkpoint 不负责还原磁盘上的代码。

## 长期记忆生命周期

新请求 -> 元数据清单 -> 模型选相关 ID -> 按预算提供正文。
任务完成 -> 本次用户消息与已有记忆 -> 模型提出增删改 -> 校验 -> 原子保存。
空列表也是正常结果。提取请求失败时报告未保存，不执行候选操作，不影响已完成的代码任务。
没有提取后台线程、定时整理器或向量索引。来源检查只能确认引用存在，不保证每条语义判断正确。

## 正确性与实现范围

模型的最终文本只是提交完成的请求。`completion.py` 先检查未确认副作用，再运行用户配置的
验证命令，保存验证结果，最后复查观察到的文件状态。验证失败或文件变化都会反馈模型继续修复。
验证命令自身改变可见工作区时也不能直接通过；应检查变化并重新验证。

Session 只保存最近一次验证记录、是否必须验证和未确认副作用清单。没有结果的读取调用可以
直接补记中断；编辑调用需要重新读对应文件；Shell 和验证命令的不确定结果反馈模型继续检查。
Session 记录后续真实观察调用的历史位置，不接收模型自报的“已确认”，也没有人工解锁接口。
这些引用只说明执行过观察，不证明所有影响已经解决；检查相关性由模型判断。局部验证通过后
可以结束本地任务，但未确认影响仍写入最终回答和报告。远程或不可逆操作无法核实时，模型应
报告具体阻塞并请求帮助，不盲目重试；本版不通过命令关键词猜测风险。
恢复时不复用以前的通过结果，也不自动重放命令。未完成任务的验证要求不能通过移除配置取消。
Session 不使用版本标签；加载时校验实际字段、执行状态和工作区归属，不提供迁移分支。

文件复查复用 Shell 已有的工作区观察，只覆盖可见文件。它解决“测试通过后文件又被修改”
这一具体问题：Git 提交版本不代表未提交内容，类型和测试结果也不会自行绑定后续文件状态。
这不是跨进程事务，不能证明外部服务状态或所有用户需求正确。未配置验证且没有待处理要求时，
允许结束任务，但不宣称验证通过。当前验证配置与最后执行记录分开展示；尚无执行时记录为 `not_run`。新请求保留失败或中断记录，旧通过记录标为 `stale`，完成判定仍重新验证。

文件替换、命令超时、会话保存都有具体失败语义；不维护通用工作流状态机。
所有主模型轮次，包括格式错误和验证失败后的修复，都消耗 max_turns。
记忆、摘要和只读子任务共享剩余时间；超时停止真实 HTTP 或命令执行，而不只检查循环开头。
本版是单机、单 Session 写入者、可信仓库的教学实现，不提供沙箱或跨进程事务保证。

原版 LayeredMemory、XML/JSON 文本协议、Checkpoint 内重复任务进度、旧 provider 分支已退出新代码。
旧两个项目完整保留，新目录没有兼容垫片。测试未执行前不宣称运行稳定或收益提升。

摘要正文预算与 API 生成额度分别管理：生成额度包含模型推理，输入分块时为其预留空间；最终摘要仍必须满足正文长度限制，超长或生成中断不推进覆盖位置。

## 工具失败与恢复指引

参考原版 FailureInfo 的恢复条件语义，保留现有 ToolResult，直接增加 recovery 对象。
error 是错误码；recovery.condition 表示 retry_after_change、retry_after_wait、user_action_required
或 no_retry；requirement 说明恢复前提，action 说明具体动作，suggested_call 提供可确定的工具与参数。
当前本地工具没有需要自动等待恢复的已确认场景，因此不会凭空返回 retry_after_wait。
成功结果 recovery 为 null。建议不会自动执行，不构成授权，也不代替下一次参数和权限检查。

版本冲突同时返回 expected_revision、actual_revision 和 read_file 参数；匹配失败返回位置与读取范围。
范围违规明确禁止 Shell 绕过，审批拒绝停止重复请求；Shell 超时或未知影响先观察实际状态。
命令非零退出保留退出码和输出，不仅凭错误文字猜测修复位置。
取消与总预算耗尽要求先停止，不能借恢复建议继续自动操作。

Session 格式为 v8，恢复补写的中断结果也带 recovery；旧格式直接拒绝。
本次更新只进行了静态和格式检查，新增回归用例尚未执行。此前测试成绩不代表这个版本通过。

## 重复失败与停止

Session.loop_control 保存连续无效输出、完成拒绝、最近一次失败条件和已拒绝审批。
连续 8 次无效输出停止；连续 3 次同类完成拒绝停止，不因任意工具调用清零。
对整个工作区执行的 verifier，在确认发生工作区变更后重新计数；有明确路径的拒绝只由交集路径
变更触发重计。这说明旧验证状态发生变化，不证明修改在业务上正确。

文件／参数类确定性失败比较工具、校验后的参数、已有版本与读取版本等事实。第二次明确提醒，
相同条件第三次停止自动任务；当前回复中尚未执行的调用补记为未启动，不能成为未知副作用。
无关成功读取不清零；读取相关目标解决了读取前提或发现新版本、相关目标确认变更后可重新计数。
Shell 的实际执行失败只提醒，不缓存命令结果或按命令字符串禁止重跑；Shell 的审批拒绝等执行前
确定性拒绝仍适用限制。总轮数和时间预算继续约束所有调用。

审批拒绝按工具和校验后参数（文件路径规范化）记录，先保存再返回；后续相同操作不再次弹审批。
未完成 Session 恢复保留记录，切换 auto 也不默默推翻既有拒绝。用户可显式 /retry-denied，随后仍走
正常审批与权限检查；此入口不暴露给模型。没有同轮读取合并、全局缓存或任务进展评分。
本次改动未执行测试或真实模型调用，已有成绩不代表该版本通过。

最新执行链已加入 pending/running/finished 阶段、Session 级 Artifact、文件前像与收据、任务净 Diff和有限只读并行。详见 [执行与证据](execution-and-evidence.md)；历史说明中的串行执行及截断后不可取回范围，以该文档为准。

## 本次基础能力迁移

- Workspace 分别保存启动目录、工作区根和 Git 根。默认发现 Git 顶层；显式 `workspace_root` / `--workspace-root` 固定较小边界。所有相对工具路径、Session、Artifact、RepoMap 和交付报告采用同一工作区根。
- 每轮 Prompt 获取只读 Git 短状态，列出分支、已有修改与冲突；输出限长，失败标记未知。只加载工作区根 AGENTS.md。Git 观察不扩大权限，也不提供沙箱。
- `allowed_tools` 与模式、子代理限制取交集；Schema 和执行器共用筛选逻辑。文件写入范围另行规范化，审批展示实际目标与操作。配置的 Runtime 验证命令独立于模型工具白名单，仍执行原审批和完成检查。
- read_file 分块扫描计算完整版本，只保存有界目标行；search 使用 ripgrep 字面搜索，遵循默认忽略规则，不搜索隐藏文件、不跟随符号链接，保留内部目录排除。最多展示 200 条匹配，命令共享任务期限。
- 命令与完成验证的观察保留原文件内容比较，额外比较 Git HEAD、分支引用、工作区范围内的暂存区。Git 状态变化与 changed_paths 分开展示；不声称覆盖远程或所有外部副作用。
- Session 校验加载身份、用户请求位置和执行记录，无版本标签和自动迁移。失败纠偏最多保留 8 种近期失败，识别交替失败；相关输入、成功重试或文件变化可解除对应记录。正常成功读取不按失败拦截。
- RepoMap 查询结合当前请求、历史摘要与本次相关路径；摘要只是定位线索，不授予权限或证明文件当前内容。
